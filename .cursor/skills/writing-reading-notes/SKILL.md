# 读书笔记（读后感）

把摘抄和个人想法写成一篇带感受的读后感，不是书摘提纲。

## 输出是什么

一篇顺着阅读走下来的文章：有书里的场景和判断，也有读者自己的看法。读者读完应感到「这人读过、想过」，而不是「这是目录扩写」。

**不是：** 按章节罗列「要点 / 摘抄 / 想法」；把书中观点凝练成条目；给每章贴标签。

## 工作流程

1. **收原料。** 用户贴的摘抄、书目文件夹里的 `笔记原文.txt`、`想补充的总体感受.txt` 全部保留实质，去重即可。感叹词可忽略：嗯、确实、神奇、是啊、哇、确实哦。有内容的想法必须写进正文，不要单独挂成「想法：」列表。总体感受不是附录，要进 Overview，并用来刷新后文的接法，不要只改开头一段。
2. **补全书脉络（需要时）。** 可联网查全书结构，用来把摘抄接上，不拿二手书评替换用户原文。
3. **先写 Markdown 读后感。** 按阅读感受推进，可用主题小标题（如「自由会不会成为负担」），不要用「第一章」「第二章」。
4. **再出无格式版。** 同一篇文章，去掉标题符号、加粗、引用块、表格、链接；写成连贯散文，不要按章节切块。供粘贴到书评/评论。
5. **落盘并更新索引。** 用户后补总体感受时：改 Markdown、同步无格式版、把感受原文归档进摘抄原文；用户自己的 `.txt` 原件保留不删。

## 文风

- 用「读到……会觉得……」把书和人接上，不要先抛概念再解释。
- 书中关键原句可直接引入，但要用自己的话接住。
- 个人判断嵌在叙述里，例如「所说的和真实动机并不一致」「心理历程无法跳跃」。
- 口吻平实、完整句子。不要清单腔，不要「本章在全书中的位置」。
- Overview 直接写这本书碰到了什么、读完留下什么判断。不要「一开始会以为……读下去才发现」「本来以为……其实是」这种先设靶再翻盘。
- 结尾收在读完还留下什么，不要再做一次全书摘要。

## 文件与命名

每本书一个根目录文件夹，与已有书目并列（如 `逃避自由/`、`以日为鉴/`）。文件夹用中文书名，各版本笔记都放在里面。

| 文件 | 路径 |
|------|------|
| 微信读书原始导出（若有，只归档、不改） | `<书名>/笔记原文.txt` |
| 用户后补的总体感受（若有，保留原件） | `<书名>/想补充的总体感受.txt` |
| 摘抄原文（只整理、不改意见） | `<书名>/读书笔记-摘抄原文.md` |
| Markdown 读后感 | `<书名>/读书笔记.md` |
| 无格式版 | `<书名>/读书笔记-无格式版.txt` |

不要按作者拆 `raw/<topic>/`、`wiki/<topic>/`。新书在仓库根目录新建文件夹，不要塞进已有书的目录。`wiki/` 只放总目录：`index.md`、`log.md`。

Markdown 文首：

```markdown
# 《书名》读书笔记

> Sources: 作者，《书名》，出版年；译本信息；阅读摘抄与想法 YYYY-MM 至 YYYY-MM
> Raw: [摘抄原文](读书笔记-摘抄原文.md)
```

然后是 `## Overview`（直接写读完留下的总判断，不要「本来以为」句式）和若干主题小节。

落盘后更新：

- `wiki/index.md` — 一行：链接、一句话摘要、日期
- `wiki/log.md` — 追加 `## [YYYY-MM-DD] ingest | 书名 读书笔记`（补写则用 `update`）
- `README.md` — 笔记列表加上新书

本仓库文件命名以本 skill 为准，不要改用英文 kebab-case。

## 无格式版

从读后感抽出正文，做成一篇可粘贴的散文：

- 去掉 `#`、`**`、`>`、表格、链接、YAML
- 不用「第一章」或目录式小标题；段落之间靠句子转下去
- 不要出现「整章的压轴」「附录把方法收束」这类章节导游句

用户若只要评论版，只给无格式版，并说明字数。

## 反例 / 正例

反例（不要这样）：

```
## 第三章 宗教改革时代的自由
### 要点
- 路德的臣服被说成爱
### 想法
- 2026/07/15：所说的和真实动机并不一致
```

```
读《以日为鉴》，一开始会以为它在讲日本宏观史。读下去才发现……
```

正例（要这样）：

```
路德说自己对上帝的臣服是自愿的，出于爱而非恐惧。从心理结构看，这种爱就是臣服。
读到这里会立刻想起：所说的和真实动机，本来就不一致。
```

```
这本书写日本的就业、教育、人口、医疗，每一条都能看见现在国内的影子。
```

## 常见错误

| 借口 | 实际 |
|------|------|
| 「按章节写才不会漏」 | 漏不漏靠是否吃进摘抄，不靠目录骨架 |
| 「先总结再写感受」 | 感受要写进叙述，不要附录化 |
| 「无格式版就是去 Markdown」 | 还要把章节块打成一篇文章 |
| 「感叹也算想法」 | 嗯、确实、神奇丢掉；有判断的句子留下 |
| 「Overview 先写预期再翻转更有层次」 | 直接写判断；「本来以为」是话术，不是层次 |
| 「总体感受放 Overview 就够了」 | 后文的接法也要按这个判断刷新 |
| 「按作者建 raw/wiki 子目录」 | 每本书一个根目录文件夹 |

## 完成前自检

- [ ] 不是章节提纲
- [ ] 用户的实质摘抄都在（可改写嵌入，不可丢掉）
- [ ] 有内容的个人想法、总体感受已写进正文（含后文，不只 Overview）
- [ ] Overview 没有「本来以为 / 一开始会以为 / 读下去才发现」
- [ ] Markdown 版 + 无格式版都有
- [ ] 落在 `<书名>/` 下：`读书笔记.md` / `读书笔记-无格式版.txt` / `读书笔记-摘抄原文.md`
- [ ] index、log、README 已更新
